## 2024-04-09 - [Streamlit Rerun Loop Allocations]
**Learning:** Streamlit reruns the entire script on every user interaction. Defining static lists inside rendering loops causes redundant memory allocations and garbage collection overhead on every rerun. For small literal collections in `in` checks (e.g. `c2 in ["A", "B"]`), CPython optimizes them better if they are tuples, avoiding list creation overhead entirely.
**Action:** Always hoist static arrays (like `YKSIKKO_OPTS_BASE`) outside of loops to reuse references, and prefer tuples over lists for static options or membership checks to minimize allocation overhead per rerun.
## 2024-04-10 - [Streamlit Re-renders and Pre-calculating State]
**Learning:** In Streamlit, the entire script is executed top-to-bottom on every single interaction (like changing a selectbox). Iterating over the main data dictionary to find unique items or filter available protocols inside the main render path causes redundant O(N) operations per interaction, generating unnecessary overhead and GC churn. By shifting the generation of derived UI states (like unique cancer types and filtered protocol mappings) into the `@st.cache_data` data-loading function, we convert this continuous O(N) cost into a one-time operation, enabling fast O(1) dictionary lookups in the UI rendering code.
**Action:** Always pre-calculate and cache derived UI state mappings (e.g. dropdown options and their corresponding filtered lists) alongside the main data load to ensure fast O(1) UI reruns.
