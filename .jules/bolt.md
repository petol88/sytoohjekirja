## 2024-04-09 - [Streamlit Rerun Loop Allocations]
**Learning:** Streamlit reruns the entire script on every user interaction. Defining static lists inside rendering loops causes redundant memory allocations and garbage collection overhead on every rerun. For small literal collections in `in` checks (e.g. `c2 in ["A", "B"]`), CPython optimizes them better if they are tuples, avoiding list creation overhead entirely.
**Action:** Always hoist static arrays (like `YKSIKKO_OPTS_BASE`) outside of loops to reuse references, and prefer tuples over lists for static options or membership checks to minimize allocation overhead per rerun.
## $(date +%Y-%m-%d) - [Pre-calculate Streamlit Derived States]
**Learning:** In Streamlit, computing derived UI state (like dropdown options and filtered mappings) dynamically in the render loop causes significant O(N) overhead on every user interaction. Returning only raw data from a `@st.cache_data` function isn't enough if the UI immediately loops over that large data structure.
**Action:** When working with Streamlit apps that load large datasets, always move the derivation of UI-specific collections (lists, filtered maps) into the `@st.cache_data` loading function. Return a tuple containing both the raw data and the pre-calculated $O(1)$ lookups to eliminate iteration overhead during reruns.
